# БСБ — MVP сервиса заказа бетона с доставкой

Тестовый MVP веб-сервиса для организации поставок бетона и стройматериалов.
Клиент оформляет заказ → заказ видят подходящие заводы → первый завод, нажавший
«Взять заказ», получает его → клиент видит статус и данные завода.

## Стек

- **Frontend:** Next.js 14 (App Router), React, TypeScript, Tailwind CSS
- **Backend:** Next.js Server Actions
- **База данных:** PostgreSQL + Prisma ORM
- **Авторизация:** email/пароль, роли `CLIENT` / `PLANT` / `ADMIN`, сессия — подписанная cookie (без внешних библиотек)

## Что уже реализовано (MVP)

- Регистрация и вход, 3 роли с разграничением доступа через `middleware.ts`
- Пошаговый wizard заказа бетона (материал → марка → характеристики → количество →
  насос → адрес → дата/время → контакты → подтверждение), с гостевым оформлением
  (можно создать аккаунт прямо на шаге контактов, не проходя отдельную регистрацию)
- **Атомарная логика «кто первый — тот получил»** (`app/actions/plants.ts → takeOrder`):
  несколько заводов видят заказ одновременно, но назначить его себе может только один —
  это гарантируется транзакцией и условным `UPDATE` в PostgreSQL (см. комментарий в коде)
- Личный кабинет клиента со списком заказов, статусом и историей
- Личный кабинет завода: новые / принятые / завершённые заказы
- Админка: dashboard со статистикой, таблица всех заказов с фильтрами и ручными
  действиями (сменить статус, отменить, назначить завод вручную), список заводов
  (создание/редактирование/деактивация), список клиентов, упрощённая карта заводов
- Seed-скрипт с 10 тестовыми заводами Москвы и МО и тремя демо-аккаунтами
- Обновление статусов без перезагрузки — через polling каждые 6–7 секунд (см. раздел
  «Realtime» ниже)

## Что упрощено или не реализовано (сознательно, по ТЗ MVP)

- Онлайн-оплата, интеграция с 1С, SMS, полноценная CRM, сложное ценообразование —
  не реализованы (см. п. 41 исходного ТЗ)
- **Геокодирование адреса и интерактивная карта с перетаскиваемой меткой** — в MVP это
  текстовое поле адреса + ручной ввод широты/долготы (по умолчанию — центр Москвы) и
  статичная схема-заглушка. В боевой версии — интеграция с Яндекс.Geocoder API
  (нужен API-ключ)
- **Карта заводов в админке** — простая SVG-схема с относительным расположением точек,
  без реального картографического провайдера (тоже требует API-ключ Яндекс.Карт/2ГИС)
- **Realtime** — реализован через polling (опрос сервера раз в 6–7 секунд), как и
  допускает ТЗ (п. 40) для обычного PostgreSQL. Для перехода на настоящий realtime
  проще всего мигрировать на Supabase и использовать Supabase Realtime, либо добавить
  WebSocket-сервер

## Структура проекта

```
app/
  actions/        Server Actions (auth, orders, plants, admin) — вся бизнес-логика
  order/new/       Wizard оформления заказа (клиентский компонент)
  client/orders/    Личный кабинет клиента
  plant/            Личный кабинет завода
  admin/            Админка (dashboard, orders, plants, clients, map)
  login/ register/  Страницы входа и регистрации
components/        Переиспользуемые UI-компоненты
lib/               Prisma-клиент, сессии, хэширование паролей, утилиты
prisma/            schema.prisma и seed.ts
middleware.ts      Защита /admin, /plant, /client по ролям
```

Бизнес-логика полностью отделена от UI: все запросы к базе идут через `app/actions/*`,
компоненты страниц только вызывают эти функции.

## Локальный запуск

### 1. Установите зависимости

```bash
npm install
```

### 2. Поднимите PostgreSQL

Проще всего — через Docker:

```bash
docker compose up -d
```

Если Docker недоступен — используйте любой локальный/облачный PostgreSQL
(например, Supabase) и просто укажите его адрес в `DATABASE_URL` на следующем шаге.

### 3. Настройте .env

```bash
cp .env.example .env
```

Значения по умолчанию в `.env.example` уже подходят под `docker-compose.yml`.
Для продакшена обязательно замените `SESSION_SECRET` на случайную строку:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### 4. Сгенерируйте Prisma Client и примените миграции

```bash
npm run db:generate
npm run db:push
```

> `prisma generate` скачивает движок Prisma с `binaries.prisma.sh` — для этого
> нужен доступ в интернет (или заранее закэшированные бинарники / offline-мирроp,
> если вы работаете в закрытом контуре).

### 5. Заполните базу тестовыми данными

```bash
npm run db:seed
```

Создаст 10 тестовых заводов и три демо-аккаунта:

| Роль    | Email              | Пароль      |
|---------|--------------------|-------------|
| Админ   | admin@bsb.test     | Admin123!   |
| Завод 1 | plant1@bsb.test    | Plant123!   |
| Клиент  | client@bsb.test    | Client123!  |

(Заводы 2–10: `plant2@bsb.test` … `plant10@bsb.test`, тот же пароль.)

### 6. Запустите dev-сервер

```bash
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

## Тестовый сценарий (соответствует п. 34 ТЗ)

1. Откройте сайт, нажмите «Заказать бетон».
2. Пройдите wizard: Бетон → М300 → 10 м³ → насос 36 м (Автобетононасос) → укажите
   адрес в Москве → выберите дату и время.
3. На шаге контактов, если вы не вошли — укажите email и пароль (аккаунт создастся
   автоматически) — либо предварительно зарегистрируйтесь через «Войти → Зарегистрироваться».
4. Подтвердите заказ — увидите статус «Ищем завод».
5. В другой вкладке/окне инкогнито войдите как `plant1@bsb.test / Plant123!` —
   увидите заказ в разделе «Новые» на `/plant`.
6. Нажмите «ВЗЯТЬ ЗАКАЗ» — заказ закрепится за заводом №1.
7. Войдите как `plant2@bsb.test / Plant123!` — этот же заказ уже не появится в списке
   доступных (или при прямой попытке взять — вернёт «Заказ уже забрал другой завод»).
8. Вернитесь в кабинет клиента — статус сменится на «🟢 Завод найден» (обновится
   автоматически в течение ~7 секунд благодаря polling, либо сразу при обновлении страницы).

## Проверка «гонки» между заводами

Чтобы убедиться, что логика действительно атомарна, можно параллельно отправить два
запроса на принятие одного заказа (например, открыв заказ в двух вкладках под разными
заводами и быстро нажав кнопку в обеих) — успешным будет только один запрос, второй
получит понятную ошибку. Атомарность обеспечивается на уровне БД (см. комментарий в
`app/actions/plants.ts`), а не в UI, поэтому она работает даже при реальных
одновременных запросах, а не только в интерфейсе.

## Деплой

Для тестового размещения в интернете подходит любой хостинг с поддержкой Next.js
(например, Vercel) — потребуется:
1. Управляемый PostgreSQL (Vercel Postgres, Supabase, Railway и т.д.);
2. переменные окружения `DATABASE_URL` и `SESSION_SECRET`;
3. выполнить `npm run db:push` и `npm run db:seed` против продакшен-базы (либо
   заменить seed на реальные данные заводов).

## Telegram-бот

Бот уведомляет заводы о новых заказах, клиентов — об изменении статуса, админов —
о новых заказах, и умеет отвечать на базовые вопросы (цены, марки бетона, доставка).
Реализован без внешних библиотек — вебхук в `app/api/telegram/webhook/route.ts`.

### 1. Создайте бота

В Telegram напишите [@BotFather](https://t.me/BotFather):

```
/newbot
```

Укажите имя (например «БСБ — бетон с доставкой») и username, оканчивающийся на `bot`
(например `bsb_beton_bot`). BotFather выдаст токен вида `123456789:AA...` — это
секрет, храните его только в `.env`, никогда не коммитьте и не пересылайте в чатах.

### 2. Заполните .env

```bash
TELEGRAM_BOT_TOKEN="токен из BotFather"
TELEGRAM_WEBHOOK_SECRET="любая случайная строка, например из node -e \"console.log(require('crypto').randomBytes(16).toString('hex'))\""
NEXT_PUBLIC_TELEGRAM_BOT_USERNAME="bsb_beton_bot"
```

### 3. Примените миграцию БД

В `prisma/schema.prisma` у `User` появились поля `telegramChatId` и `telegramLinkCode`:

```bash
npm run db:push
```

### 4. Задайте команды бота (необязательно, но удобно для пользователей)

```bash
npx tsx scripts/telegram-set-commands.ts
```

### 5. Зарегистрируйте webhook

Telegram должен уметь достучаться до `/api/telegram/webhook` по HTTPS. Для локальной
разработки понадобится туннель, например [ngrok](https://ngrok.com/): `ngrok http 3000`,
затем используйте выданный ngrok-адрес вместо продакшен-домена. После деплоя — используйте
реальный домен:

```bash
npx tsx scripts/telegram-set-webhook.ts https://ваш-домен.ru
```

### 6. Привяжите аккаунт

В личном кабинете (клиент/завод/админ) появилась карточка «Подключить уведомления
в Telegram» — по кнопке генерируется код, который нужно отправить боту командой
`/link КОД`. После этого уведомления начнут приходить автоматически.

### Что бот умеет уже сейчас

- `/start` — приветствие и краткая инструкция
- `/link КОД` — привязка аккаунта с сайта
- `/status` — статус последних заказов (для клиентов)
- Автоматические уведомления: заводам — о новых доступных заказах, клиентам — о
  назначении завода и смене статуса, админам — о новых заказах
- Простой FAQ по ключевым словам (цены, марки бетона, доставка, насос, сертификаты,
  контакты) — без ИИ, на данных из `lib/company.ts`

### Что не реализовано (следующий шаг)

- Отдельное Telegram Mini App (полноценный интерфейс заказа внутри Telegram,
  не только команды/текст) — отдельная задача
- Оформление заказа целиком через переписку с ботом (сейчас можно только следить
  за статусом и получать уведомления)
